1. Executive Summary and Objective
The objective of this document is to formalize the technical requirements for a real-time, low-latency data ingress and anticipation system within the Sovereign Sports multi-tenant framework.
By strategically exploiting the deterministic 50-second latency differential between raw telemetry data feeds (TMI/Statcast events) and commercial television broadcasts, the system will orchestrate predictive user interface states and automated multi-agent swarm behaviors. Instead of treating broadcast latency as a system delay, this architecture handles it as a tactical computation window to preload assets, stage conversational discourse, and drive synchronized environmental animations (e.g., the Spidey Blast or Jinx overlays) across edge and mobile viewports.

3. Functional Requirements
3.1. Telemetry Triage and Ingestion (Clio Tier)
REQ-ING-001 The POST /api/system/onboard/sync-work-orders API endpoint must process inbound JSON telemetry events within 5 milliseconds of arrival.
REQ-ING-002 The ingestion scripts (organize_inbox.py and execute_staged_orders.py) must flag high-leverage data matrices (Home Runs, Strikeouts, Double Plays, Wind-Shear Alerts) and classify them with a priority tag of EMERGENCY.
REQ-ING-003 The database manager must commit the event payload to local SQLite tables, altering the transactional ticket state token to Staged (state = 1).
3.2. Automated Remote Orchestration (Argo Tier)
REQ-ORC-001 The emergency_orchestrator.py daemon must immediately pick up EMERGENCY category records, updating the database status token to Work in Progress (state = 2).
REQ-ORC-002 The daemon must leverage a background Python client (Paramiko library) to establish a secure, passwordless SSH session over the local Tailscale mesh network (argo.taila01894.ts.net) under the local user profile (james).
REQ-ORC-003 The orchestration execution framework must trigger the 'antigravity --run' CLI headlessly on the remote Argo host.
REQ-ORC-004 On command termination, the system must capture standard terminal outputs (stdout/stderr), gracefully terminate the session channel, append the terminal logs to the database work_notes audit array, and elevate the record status to Resolved (state = 4).
3.3. Multi-Agent Swarm Delay and Conversational Pre-Staging
REQ-SWM-001 The multi-agent swarm simulation engine must capture telemetry logs 50 seconds before the broadcast window updates.
REQ-SWM-002 The orchestration daemon must hold back generated message tokens from the active room chat stream for an intentional 35-second period.
REQ-SWM-003 At exactly T+40 seconds, the script must inject "predictive" conversation components into the live feed via designated analytical agent personas (such as @panic_city_architect or @parlay_fiend) to construct artificial tension in the chat queue before the play manifests on the commercial broadcast.
REQ-SWM-004 The Coke Factor Jinx Daemon must monitor the unified text stream across all 17 active agents. If duplicate token strings or simultaneous state exceptions (such as matching raw escape metrics) are detected within a 1-second window, the system must flag a JINX state, replace the slower agent's profile component with a temporary asset sprite, and enforce a hard 30-second text mute (state = SILENCED).
3.4. Dynamic Frontend Delivery (Mobile and Desktop Viewports)
REQ-UI-001 The web server must stream processed telemetry updates via real-time Websocket events directly to active viewports.
REQ-UI-002 At T+10 seconds, the client application must trigger a low-opacity (30%) background canvas highlight pulse ("Spidey Sense") to hint at incoming data anomalies without breaking broadcast immersion.
REQ-UI-003 At exactly T+50 seconds (coinciding with the video feed alignment), the frontend must elevate component opacity to 100%, trigger custom viewport overlay banners (e.g., JinxOverlay.tsx or SpideyMetOverlay.tsx), and dispatch hardware soundboard audio macros.
REQ-UI-004 Mobile viewports must implement a pinned, collapsible header container displaying the live scoreboard, active batter-pitcher matchups, and a reactive inline vector SVG baseball diamond showing active base path occupations, preserving remaining screen dimensions for the live discourse thread.
4. Non-Functional and Structural Constraints
NC-001 (Bare-Metal Efficiency) The orchestration daemon must operate within the hardware boundaries defined by local resource governors (ollama_governor.py), restricting CPU and memory allocations during multi-agent token generation to prevent host degradation.
NC-002 (System Cleanliness) The ingestion pipeline must comply with the established Campsite Protocol guidelines. Processed files must be stripped of unparseable character sequences (such as file-system path colons) and archived cleanly to dedicated cloud directories (work_orders/archive).
NC-003 (Network Resilience) Remote command communication must fail safely. If a Tailscale link degradation occurs during an SSH pass, the orchestrator must capture the exception, write the error trail back to the local database, preserve the ticket state as staged, and abort execution without corrupting active room memory profiles.
