## What Broke During Session (And Whether It Was Fixed)
This session was an absolute marathon of compounding networking and security failures:
1. **The "Secure DNS" Silk Browser Failure**: We initially assumed the Silk Browser couldn't connect because of an invalid Let's Encrypt certificate. This was false. Silk was using a forced "Secure DNS" that resolved to the public Tailscale IP instead of the MagicDNS local IP.
2. **The HTTP Downgrade / HSTS Lockout**: In an attempt to fix Silk, I downgraded the Cinema Vite server to raw HTTP. This caused Chrome on the laptop to throw an `ERR_SSL_PROTOCOL_ERROR` because Chrome caches HSTS for `taila01894.ts.net` and aggressively rejected the HTTP connection.
3. **The "White Screen" Cached Service Worker Trap**: Once the TV finally resolved the right IP, we attempted to hit port 3008 natively. Instead of loading the Cinema, Silk loaded a phantom cached version of the *Sovereign Portal* (which used to live on 3008 in a previous sprint). The cached Service Worker completely intercepted the request, leading to endless timeouts. 
4. **The Tailscale Port 8448 Rejection**: We attempted to map the Cinema to a Tailscale proxy on port 8448. The laptop worked, but the Fire TV Android Tailscale client aggressively blocked the non-standard port.
5. **The Proxy Redirect Loop**: Finally, we tried to route the Cinema through the main Portal proxy on port 443 at `/cinema-portal/`. But Vite's `base` path collided with the proxy's `rewrite` rule, causing an infinite redirect ping-pong loop.
**Resolution**: We stripped the rewrite rule, routed everything cleanly through the standard `443` port via `/cinema-portal/`, fixed the CSS overlaps, and defeated the TV.
