# Walkthrough - DFCT0000478

## Problem Statement
The "Sign Out" / logout button on the Sovereign OS Portal failed to clear active user sessions. Clicking it temporarily reloaded the screen, but the user remained logged in. This prevented the Pilot from logging out to test separate user presence profiles (like switching to Pawel/Patron) for HoloLink UAT testing.

Additionally, during UAT:
1. Patron users (like Pawel) did not have the new dynamic `HololinkHub` component mounted in the decoupled FanStack portal (`15_FanStack`), meaning they had no telepresence roster.
2. The `/ws-relay` WebSocket proxy inside `15_FanStack/vite.config.ts` was pointing to the old legacy port `8008` instead of the correct `8012` mesh signaling relay port.
3. Pawel's user role required elevation to `pilot` to align session presence and dashboard views with James.

## Root Cause Analysis
*   **Logout Bug:** When a user logs in, the application stores the session JWT token in **both** `localStorage` (as `sovereign_session_token`) and a cookie (`sovereign_session_token`). The legacy `handleLogout` function inside `GlobalSystemBar.tsx` only deleted the key from `localStorage`, then forced a page reload. Upon reload, `AuthGate.tsx` found the token in the cookie, restored it to `localStorage`, and logged the user back in.
*   **HoloLink Decoupled Presence Gap:** The decoupled FanStack portal had no dynamic `HololinkHub` mounted and its Vite config proxied WebSocket traffic to port `8008` (fancast) instead of `8012` (mesh signaling).

### 1. Front-End Header Dropdown Fix
Modified `handleLogout` in `GlobalSystemBar.tsx` across all micro-frontends:
*   `[GlobalSystemBar.tsx](file:///home/james/SovereignOS/01_Sovereign_Portal/src/components/GlobalSystemBar.tsx)`

The updated `handleLogout` calls the auth context's `logout()` function (which clears the cookie cleanly), falls back to clearing the session cookie directly, clears `localStorage`, and reloads the screen.

### 2. Back-End Core API Route Added
Added a standard stateless POST route for logout in `sovereign_core_api.py` to allow the system to conform to server-side logout specifications:
*   `[sovereign_core_api.py](file:///home/james/SovereignOS/scripts/sovereign_core_api.py)`

### 3. FanStack HoloLink Integration & Proxy Correction
*   Copied `HololinkHub.tsx` into `15_FanStack/src/components/` and mounted it at the bottom of the App render tree in `[App.tsx](file:///home/james/SovereignOS/15_FanStack/src/App.tsx)`.
*   Corrected `/ws-relay` proxy target in `[vite.config.ts](file:///home/james/SovereignOS/15_FanStack/vite.config.ts)` from `ws://127.0.0.1:8008` to `ws://127.0.0.1:8012` to route WebSocket traffic to the mesh signaling server.

### 4. User Role Elevation
*   Upgraded Pawel's role to `pilot` in `sys_user` in the `sovereign_now.db` ledger.

### 5. Resilient Telepresence Reconnect Loop (UAT Fix)
*   Refactored the WebSocket connection logic inside `HololinkHub.tsx` (both in `[HololinkHub.tsx](file:///home/james/SovereignOS/01_Sovereign_Portal/src/components/HololinkHub.tsx)` and `[HololinkHub.tsx](file:///home/james/SovereignOS/15_FanStack/src/components/HololinkHub.tsx)`) to recursively reconnect and automatically register clients after connection losses (e.g. during dev server restarts or network glitches). This resolved the UAT issue where a client would appear online to others but fail to see them in return due to a stale unregistered socket.
